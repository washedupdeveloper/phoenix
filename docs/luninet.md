# luninet

This machine joins **luninet**, the computer-club's WireGuard mesh
(`github:the-computer-club/luninet`, pinned in `flake.lock`). The change is on the branch
`feat/luninet` and is deliberately the *minimum* that connects: one interface, the peer list
from the pinned input, and nothing else — no listen port, no DNS, no keepalive.

## Joining, in order

**1. The keypair already exists.** It was minted into the vars store by the `luninet`
generator (`machines/workstation/configuration.nix`), which runs

```console
wg genkey > $out/key; wg pubkey < $out/key > $out/pubkey
```

The private half never leaves the store — age-encrypted at rest, deployed to
`/run/secrets`, never the Nix store. Read the public half back with:

```console
nix develop -c clan vars get workstation luninet/pubkey
```

**2. Open the pull request upstream.** In `the-computer-club/luninet`, `peers.nix` takes one
entry per member; the name becomes the `.luni` hostname:

```nix
  workstation.publicKey = "cSvaSSxlFd/av1yWj7pq8Qofa3d+cmx/E5hzsCFQ0z0=";
  # ipv4 = [ "172.29.80.12" ];   # only if you skip `nix run .#update-inventory`
```

`inventory.json` is generated by the club (`nix run .#update-inventory`); the assigned block
is `172.29.80.0/23` and its last entry is `.11`, so `.12` is the next free address if you
hardcode one. `docs/joining.md` upstream still says to fork `automous-zones` — that repository
is this one, renamed, so the pull request goes to `luninet`.

**3. After it merges:** `nix flake update luninet` (the peer list is data from the pinned
input, so this is the only thing that changes who you can reach), then
`sudo nixos-rebuild switch`. `ips` fills in from the merged entry and the interface comes up
with the address.

**4. Verify:** `ip addr show asluni`, `sudo wg show`, and `ping 172.29.80.1` — the gateway is
the only peer with a stable endpoint, so it is the only one reachable without a prior session.

## What this means for the machine — measured on this tree

| | |
| --- | --- |
| interface | `asluni`, MTU 1420, systemd unit `wireguard-asluni.service` |
| peers | 11 as of the pinned revision — every registered member, each contributing its `/32` or `/64` as AllowedIPs |
| reachable-at-rest peers | **one**: the gateway at `198.12.96.43:32288`. Every other peer has no `selfEndpoint`, so a session has to be initiated (by either side) before traffic flows |
| this machine's addresses | none until the registration merges; then `172.29.80.<n>/32` and `fd49:93b:2b68:<id>::/64` |
| routing | the routes follow AllowedIPs: `172.29.80.1/24` and `fd49:93b:2b68::/48` via the gateway, each peer's `/32` and `/64` direct. The default route is untouched |
| inbound | **nothing new.** No `listenPort`, so no UDP port is opened, the firewall is unchanged, and no peer can initiate a session with this machine |
| DNS | unchanged — `.luni` names do not resolve and the system resolver is untouched |
| secrets | the private key lives in the vars store; only the public key is public, and it is the one that gets registered |
| traffic | only packets addressed inside those prefixes are encapsulated. The FAQ calls this a split tunnel; browsing and everything else go out unchanged |

## The honest blast radius

- **A peer you have exchanged traffic with can reach services that listen on every
  interface.** WireGuard learns the path from the session you start, and the session is then
  bidirectional — so the broker (`mosquitto`, TCP 1883, bound to every interface) is reachable
  by that peer, protected only by its password. If that matters: bind the broker to the LAN
  interface, or keep this interface down when it is not in use
  (`systemctl stop wireguard-asluni`).
- **The peer list is other people's keys and endpoints**, and it is read from a pinned input —
  `nix flake update luninet` is the deliberate act that changes who is on the other end.
- **This machine stays unreachable by others.** It registers no `selfEndpoint`, so it cannot be
  contacted at rest. Hosting services for the club later means three things together:
  `listenPort = 51820`, a firewall rule for it, and a `selfEndpoint` in the upstream peer list.
- **Nothing here is a commercial VPN.** Traffic *to the mesh* is relayed by members and the
  gateway; the rest of the machine's networking is exactly as before.

## Not included, deliberately

DNS (`.luni` resolution via `172.29.83.1`, upstream `docs/dns.md`), named keys for `wg show`,
`persistentKeepalive`, the `aslunip2p` peer list, and the club's flake-guard modules. Each is
an addition to the single interface above, and none is needed to connect.

Until the pull request merges, the interface is declared but **inert**: `ips` is empty, so a
switch before then changes nothing on the wire.
